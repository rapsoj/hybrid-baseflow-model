# Hybrid groundwater-forecast → streamflow model

Does a GeoSmart groundwater forecast improve 28-day streamflow forecasts? The pipeline trains
encoder-decoder transformers on the same samples – **with** and **without** the GeoSmart
forecast – and compares them on quantile loss, skill vs baselines and extreme-event detection. It runs
on a single borehole–river pair (`python main.py chilgrove`) or jointly on all eligible chalk catchments
(`all-chalk`, and the multi-seed `all-chalk-final`).

The configured model (data sources, tensor shapes, training, evaluation) is described in
[MODEL.md](MODEL.md), which is generated from `config.yaml` (`python -m pipeline.describe chilgrove`).
Per-catchment data record lengths, forecast coverage and which catchments can be used for joint training are in
[DATA.md](DATA.md) (generated by `python -m processing.describe_data`).

## What it does

| Stage | What happens | Code |
|---|---|---|
| 1. Download HDE | 15-min groundwater level, rainfall and flow for the borehole (incremental) | `pipeline/download.py` → `processing/download_hde.py` |
| 2. Download GEFS | Ensemble-mean / variance of precipitation at the borehole, per 00Z init (incremental) | `pipeline/download.py` → `processing/download_gefs.py` |
| 3. GeoSmart | **Not run by the pipeline** – download first with `python -m processing.download_geosmart ChilgroveHouse` (AWS CLI, `gwforecasting` profile), which consolidates the daily files into one `data/geosmart/chilgrovehouse/<prefix>_forecasts.csv.gz` (only the rows the model uses; individual csvs are deleted; S3 keeps the originals) | `processing/download_geosmart.py` |
| 4. Samples | One sample per day: aligned encoder / decoder / target arrays, no look-ahead | `pipeline/data.py` |
| 5. Train | Purged chronological split, train-only scaling, both ablation variants | `pipeline/train.py` |
| 6. Evaluate / store | Metrics, config and weights written per run | `pipeline/evaluate.py`, `pipeline/train.py` |
| 7. Joint chalk run | One shared model over all eligible catchments (catchment embedding, per-catchment scalers), GeoSmart variants, per-catchment / horizon / regime plots | `pipeline/multi.py`, `pipeline/multi_plots.py` |
| 8. Final run | Several seeds of the baseline vs the GeoSmart variant, aggregated metrics and plots | `pipeline/final.py` |

## Usage

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt

python main.py chilgrove                         # download + train + evaluate
python main.py chilgrove --skip-download         # use data on disk
python main.py all-chalk --skip-download        # jointly train eligible catchments, compare GeoSmart, plot per-catchment metrics
python main.py all-chalk-final --skip-download  # final run: seeds/variants from `final_run` in config.yaml (without_geosmart vs with_geosmart, 5 seeds; add `--set data.target=baseflow --run-id <id>` for the baseflow target)
python download.py chilgrove                     # download only (same as main.py chilgrove --download-only)
python download.py chilgrove --update            # top up existing local files with newer data
python main.py chilgrove --set training.epochs=20 --set data.history_days=7 --run-id test1
.venv/bin/python -m pipeline.visualize chilgrove --run-id test1
python -m pytest tests                           # unit + synthetic end-to-end tests
```

| Argument | Meaning |
|---|---|
| `borehole` | Key under `boreholes:` in `config.yaml`, `all-chalk` (joint training) or `all-chalk-final` (multi-seed comparison) |
| `--config` | Alternative config file |
| `--set a.b=value` | Override any config value (repeatable) |
| `--skip-download` / `--download-only` | Skip / stop after the download stage |
| `--update` | Top up existing local data (default: files already on disk are skipped, with no network call) |
| `--run-id` | Run name (default: timestamp) |

The `all-chalk` run uses only local data (the `--skip-download` flag is accepted but nothing is downloaded). It automatically excludes catchments without all
three HDE series, GEFS, GeoSmart ensemble members, and enough aligned samples for every
purged train/validation/test split. It trains the two shared variants with a learned
catchment embedding and scalers fitted separately on each catchment's training split.
Results are written under `results/all_chalk/<run-id>/`, including `catchment_metrics.csv`
and `catchment_metrics.png`, plus `metrics_by_horizon.png` (quantile loss, median MAE and skill vs
persistence by forecast week) and `metrics_by_regime.png` (the same metrics for baseflow- vs
runoff-dominated steps, per catchment), `variants_vs_baseline.png` and `variant_summary.csv` (every GeoSmart
variant relative to `without_geosmart`), and `random_predictions/<catchment>_predictions_random6.png` (six random
test forecasts per catchment, with vs without GeoSmart, plus the chosen origins as CSV).

GeoSmart input options are set per variant under `ablation.variants` in `config.yaml`:
`geosmart_mode: anomaly` (level minus the member's own level at the forecast origin), `geosmart_skip: true`
(linear skip from the GeoSmart channel to the outputs) and `geosmart_ensemble: mean` (ensemble mean instead of
individual members). All variants listed in the config are trained and compared.

Quick test of the real data while GeoSmart coverage is short:
`--set data.history_days=1 --set data.horizon_days=1 --set data.decoder_days=1 --set data.splits.min_samples_per_split=2`.
The first full GEFS download (~2,200 inits) takes roughly 10–15 minutes with the default `download.gefs.workers: 16` (about an hour if set to 1); limit it with `--set download.gefs.end=2020-12-31`.

## How stations and boreholes are matched

Matching is done once, offline, by `python -m processing.match_stations` (outputs in `data/matching/`), and the result is
written into `config.yaml` by `python -m processing.add_chalk_boreholes`. The pipeline itself never searches:
`boreholes.<name>.hde_stations` holds one Environment Agency (HDE) station GUID each for groundwater, rainfall and flow, and
the download uses exactly those.

`match_stations` takes every Hydrology flow station with 15-min data on a Natural England chalk river
(`data/ea`) and finds, inside the same HydroBASINS polygon (`data/hydrobasins`): the nearest 15-min groundwater
station that has a GeoSmart forecast, and the nearest 15-min rainfall station to that borehole. Each borehole keeps its
closest flow station and each catchment one borehole. Elevation and upstream/downstream position are not checked, and
only one rainfall gauge is used per catchment. GEFS precipitation is taken at the nearest 0.25° grid point to the
borehole, not as a catchment average. The stations chosen for each catchment are listed in [DATA.md](DATA.md);
Chilgrove (borehole Chilgrove House, rainfall Chilgrove House, flow Graylingwell on the River Lavant) was matched by hand
and its GeoSmart history equals the HDE groundwater level.

## Configuration (`config.yaml`)

| Section | Key settings |
|---|---|
| `paths` | Data, model and result folders (`{borehole}` is substituted). `hde_dir` must be `data/hde/{borehole}` |
| `boreholes.<name>` | Coordinates (GEFS), GeoSmart file prefix, HDE station GUIDs (groundwater, rainfall, flow) |
| `download` | `update` (skip vs top up existing files); `gefs.start`, `gefs.end`, `gefs.refresh` (full re-download) |
| `data` | `step_minutes` (15), `output_step_minutes` (360), `history_days` (14), `horizon_days` (28), `decoder_days` (28), `origin_time`, GEFS/GeoSmart availability and age limits, split fractions, extreme-event quantile |
| `model` | Transformer size (small: d_model 32, 1+1 layers, dropout 0.3), encoder patching (6 h tokens), output quantiles |
| `training` | Seed, device, epochs, batch size, learning rate, early stopping |
| `ablation` | Variants (`use_gefs`, `use_geosmart`, `geosmart_mode`, `geosmart_ensemble`, `geosmart_skip`) and `restrict_to_common_samples` |
| `final_run` | Seeds, baseline variant and GeoSmart variant for `all-chalk-final` |

Sequence lengths are derived from `step_minutes`, `output_step_minutes`, `history_days`, `horizon_days` (14 days of history → 1344 encoder steps; 28 days of output at 6 h → 112 steps).

## Model and data design

| Item | Design |
|---|---|
| Encoder input | Past `history_days` of HDE rainfall (log1p) and groundwater (+ missing-value masks), 15-min, patched (24 steps concatenated and linearly projected) into 6 h tokens: 14 days → 56 tokens, half the 112-token decoder length |
| Decoder input | One token per 6 h over `decoder_days`: GEFS ensemble mean & std of rainfall, one GeoSmart ensemble **member** trajectory of groundwater (variant 1 only; see *Ensemble handling*), season sin/cos |
| Fusion | Non-causal decoder self-attention + cross-attention to the encoder memory |
| Output | `horizon_days` × 4 flow values (112 at defaults, i.e. 4 forecast weeks) for 7 quantiles (0.05…0.95), non-crossing by construction; each 6 h decoder token emits one value, the **mean flow over that 6 h bin** (`output_step_minutes: 360`) |
| Target | HDE flow at the catchment's gauge (Graylingwell, River Lavant for Chilgrove) |
| Loss | Pinball (quantile) loss in scaled log1p space |
| Ablation | `with_geosmart` vs `without_geosmart`, identical samples, split and seed |

### Target mode (`data.target_mode`)

| Mode | Network predicts | Notes |
|---|---|---|
| `absolute` | log1p(flow) | |
| `delta_log_last` (**default**) | log1p(flow) − log1p(anchor), anchor = mean observed flow over the last `anchor_hours` (24) | The anchor is also a decoder input channel (both ablation variants). Expected to help the first weeks and baseflow-dominated periods, and to fade (or hurt) at weeks 3–4 |
| `delta_log_last_anomaly` | log1p(flow) − [log1p(clim at target day) + log1p(anchor) − log1p(clim at origin day)] | Anomaly persistence: the recent anomaly is carried forward and the network learns its change. The anchor is also a decoder input. Removes seasonal drift from the delta target |
| `anomaly` | log1p(flow) − log1p(seasonal climatology median at the target day of year) | The climatology uses training-period flow only |

All modes invert to m³/s before any metric is computed, so results are directly comparable. Judge a mode by per-week and per-regime skill (`test.week_N.*`, `test.regime.*`), not only overall loss. Chosen by a 5-seed comparison on Chilgrove (test set, mean ± sd quantile loss in m³/s): `delta_log_last` 0.062 ± 0.005/0.007 (with/without GeoSmart) vs `anomaly` 0.069/0.073 and `absolute` 0.072/0.073; week 1 is 0.027–0.029 vs 0.050–0.058, and skill vs seasonal climatology is 0.58 vs 0.50–0.53. Weeks 3–4 are about equal across modes. `delta_log_last_anomaly` (5 seeds) was worse than `delta_log_last` in all 10 paired comparisons (0.075/0.074 vs 0.062/0.062; week 1 0.037 vs 0.027–0.029; runoff-dominated 0.154–0.159 vs 0.116–0.117; skill vs seasonal climatology 0.49–0.50 vs 0.58; coverage 0.83–0.88), so it is not used. In this comparison the with- vs without-GeoSmart difference is within seed noise for every mode and week (only `anomaly` and runoff-dominated `absolute` lean towards GeoSmart). Compare modes with `python main.py chilgrove --set data.target_mode=delta_log_last --run-id <id>`.

### Ensemble handling (GeoSmart members)

The model sees **one member trajectory at a time** instead of ensemble statistics (`pipeline/ensemble.py`):

- **Training:** each time a sample is used, one of its ~44 GeoSmart members is drawn at random and fed as the groundwater channel (also a data augmentation). Validation loss (early stopping) uses 5 fixed random members per sample.
- **Inference:** the model is run once per member; each run gives 7 quantiles, which are pooled as an equal-weight mixture (quantile functions interpolated linearly, extended linearly to 0/1 and clipped at 0 m³/s; 64 draws per member). The pooled quantiles are what is evaluated, so the spread reflects both member (forcing) and model uncertainty.
- **GEFS** is still the ensemble mean and std: `download.py` only stores mean/variance over the 31 members, so GEFS members cannot be sampled without re-downloading them.
- All scaling uses one shared scale for all members, fitted on training samples; the without-GeoSmart variant is unaffected.
- Settings: `ensemble.val_members_per_sample`, `ensemble.pool_draws_per_member`.

### Alignment / leakage controls

| Risk | Control |
|---|---|
| Forecast used before it existed | Forecast origin `t0` = day + `origin_time` (12:00 UTC). GEFS: latest 00Z init with init + 6 h ≤ `t0`; GeoSmart: latest file whose last historic (ID 0) time ≤ `t0`; both ≤ 24 h old |
| Misaligned lead times | Forecasts are placed by **valid time** (GEFS `init_time + lead_time`; GeoSmart date), never by lead index |
| GEFS accumulation | mm/s rates → mm per 6 h bins; incomplete bins dropped; variances summed |
| GeoSmart members | Members are every `TimeSeriesID` ≠ 0 (ID 0 = history, used only as the common starting anchor). Files hold ~75 members for ~14 days and then a smaller subset (~44) out to ~29 days. Only the members present on the last forecast day are used (on every day), so the ensemble does not change composition mid-horizon; this needs ≥ `min_member_fraction` (0.5) of the maximum member count, otherwise only the members complete over the leading full-ensemble days are used. Each member is interpolated from daily to 6 h |
| Train/val/test overlap | Chronological split with purge gap = history + horizon (28 d default); hard assertion on window overlap |
| Scaling / thresholds | Scalers and the extreme threshold (95th percentile of historic flow) use data up to the end of train only |
| Fair ablation | Both variants use only origins where all sources exist |

### Evaluation

| Metric | Details |
|---|---|
| Quantile loss | m³/s, overall, per quantile, and **every metric below is also reported per forecast week** (`week_1` … `week_4`, in `metrics.json` under `by_week` and as `test.week_N.*` columns in the summary CSVs); plus median MAE and interval coverage |
| Baselines | Every split is also scored for **climatology** (quantiles of the training flow, no inputs) and **seasonal climatology** (quantiles of the training flow within ±`seasonal_window_days` (15) of the target day of year, training windows only) and **persistence** (flow at the origin held constant, deterministic). `skill_vs_climatology` / `skill_vs_seasonal_climatology` / `skill_vs_persistence` = 1 − model quantile loss / baseline quantile loss (> 0 means the model is better); both appear in `metrics_<variant>.json`, `comparison.csv` and `summary.csv` |
| Baseflow vs runoff regimes | Observed flow is separated with the Boughton filter on daily means (`pipeline/baseflow.py`; `data.baseflow`: k 0.95, C 0.5; restarted after data gaps). Each target step takes the baseflow index (BFI = baseflow / flow) of its day; BFI ≥ `bfi_threshold` (0.9) = **baseflow-dominated** (~46 % of days), otherwise **runoff-dominated**. Quantile loss, median MAE, coverage and skill vs climatology and persistence are reported per regime, overall and per forecast week (`metrics.json` → `by_regime`, summary columns `test.regime.<regime>.[week_N.]<metric>`). Reporting only: the split is never a model input or target and is computed from observed flow |
| Extreme events | Event = flow > 95th percentile of historic flow. FNR, FPR, precision, accuracy, F1 (also recall, event rate) from the predicted median; per time step and per forecast window |

## Caveats

| Topic | Note |
|---|---|
| Data volume | GEFS (2020-10 → present, 2,214 inits, none missing) and GeoSmart members (2020-01 → 2026-02) overlap for 1,622 usable daily samples at the 28-day horizon after purging (split 1104/244/274 with 42-day purge gaps; see DATA.md for the other catchments); a stale or partial GEFS file (e.g. only 92 inits from a limited test run) is fixed with `python download.py chilgrove --set download.gefs.refresh=true`. Training stops with an explanatory error if too few overlapping origins exist |
| Sample independence | Daily origins with 14-day windows overlap heavily, so the ~1,600 samples hold far fewer independent forecast periods (roughly one per 42 days, i.e. only ~40 independent windows) |
| Output resolution | Flow is predicted every 6 h (mean of the 15-min flow per bin, matching the 6-hourly forecast inputs); set `data.output_step_minutes=15` for the full resolution. Shapes: encoder `(1344, 4)`, decoder `(112, ≤6)`, output `(112, 7)` per sample |
| Dry period | Graylingwell flow was ≈0 in Oct–Dec 2020, so early metrics are uninformative and have no extreme events (reported as `None`) |
| Horizon | Predicts 28 days (112 six-hourly values); `horizon_days` and `decoder_days` are configurable (whole weeks only) and all shapes, targets, the purge gap and the GEFS download range follow. GEFS leads reach ~684 h, so re-download after changing the horizon |
| Time zone | All timestamps assumed UTC; HDE reporting latency is not modelled |
| GeoSmart coverage | Files exist 2020-01-01 → present, but from 2026-03 (and a few days in 2024-10, 2025-01/02) they contain only the history series, with no ensemble members, so those days are not usable samples |
| GeoSmart issue time | Files carry no issue timestamp; availability is inferred from the last history timestamp (≤ origin, ≤ 24 h old). History typically ends 06:00–12:00 on the file date, so a file may in reality be produced after the 12:00 origin on some days |
| Data ends | Flow ends ~1 week before rainfall/groundwater (latest origins need a full 14-day target), so the newest days are never used as samples |
| Flow history | Past flow is not an encoder input (rainfall + groundwater only). In `delta_log_last` mode the only flow information given to the model is the mean observed flow over the last `anchor_hours` before the origin (one decoder channel, `anchor_log_flow`), available at forecast time |

## Final multi-seed comparison

`all-chalk-final` trains `without_geosmart` and `with_geosmart` (set `final_run.geosmart` to change, e.g. `geosmart_skip`) for every seed in `final_run.seeds` and writes to
`results/all_chalk/<run-id>/`: `metrics_all.csv` (every metric by seed, variant, catchment, split, regime and forecast week),
`extreme_event_metrics.csv`, `summary_by_catchment.csv`, `metrics_by_horizon.png` (overall / baseflow-dominated /
runoff-dominated by forecast week: loss and MAE relative to the baseline, and skill vs persistence; band = seed min–max)
and `metrics_by_catchment.png`. Per-seed outputs (including random predictions) are in `seed_<n>/`.

Result of the five-seed run (`chalk-final-5seed`, 8 catchments, test set, GeoSmart with skip connection relative to
`without_geosmart`): mean quantile loss ratio 1.013 across catchments (better for Rockley 0.71, Lilley Bottom 0.94 and
Little Bucket Farm 0.97, worse for Chilgrove 1.20 and Dickley Down 1.25); median MAE ratio 0.977. By week, GeoSmart helps
mainly at week 1 (loss 0.0558 vs 0.0589) and is level by weeks 3–4; it helps in baseflow-dominated steps and is worse
in runoff-dominated steps. Several test sets are tiny (Dickley Down 17, Rockley 24 origins), so seed bands are wide.

### Predicted quantity (`data.target`)

`data.target` selects what the model predicts: `total_flow` (default, observed HDE flow), `baseflow` (Boughton filter on
daily mean HDE flow, constant within each day) or `runoff` (flow minus that baseflow, clipped at 0). The anchor and the
persistence baseline use the *previous* day's baseflow because the daily filter value includes data after the 12:00 origin.
Samples and eligibility are identical across targets (steps with missing flow stay missing). The baseflow-/runoff-dominated
regime labels are always computed from total-flow BFI. Plots use the palette `#4d1259` (GeoSmart/better), `#121c1f`
(baseline/observed) and `#0a3c8a` (extra series only).

Baseflow run (`chalk-final-baseflow-5seed`, same 8 catchments, `with_geosmart` without skip connection, test set):
mean quantile loss ratio 0.976 (GeoSmart 0.0603 vs 0.0618 overall), median MAE ratio 0.973. Rockley improves strongly
(0.55, better in 5/5 seeds), Lilley Bottom 0.93 and Farringdon 0.98; Dickley Down (1.22), Chilgrove (1.10) and
Sweeps Lane (1.02) are worse, with wide seed spread. By week, GeoSmart is slightly worse at week 1 (0.0412 vs 0.0407) and better
at weeks 2–4 (0.0527 vs 0.0553, 0.0672 vs 0.0693, 0.0802 vs 0.0821); skill vs persistence rises from 0.25 to 0.36 overall.
It helps in baseflow-dominated steps (loss 0.0542 vs 0.0598) and is worse in runoff-dominated steps (0.0836 vs 0.0773),
mostly in weeks 1–2. Quantile losses are in m³/s of baseflow, so they are not comparable with the total-flow run.
